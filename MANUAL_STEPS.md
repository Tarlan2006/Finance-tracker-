# Ручные шаги

Текущая среда уже содержит `.dev.vars` и вход Wrangler. Последнее чтение реальной таблицы: 157 расходов, 9 категорий; сводки совпали, настройки ещё не созданы. Ни одной живой записи во время разработки не выполнялось. Последняя публикация и ограничения указаны в `FIXES_REPORT.md`.

## Запустить локально утром

1. Откройте терминал в корне проекта.
2. Выполните:

   ```powershell
   npm.cmd ci
   npm.cmd run dev
   ```

3. Откройте http://127.0.0.1:5173 и введите `mock-local-key`. Это только демонстрационные данные.
4. Для реальной таблицы локально: остановите dev через Ctrl+C, выполните `npm.cmd run dev:live`, откройте http://127.0.0.1:8787. Введите существующий APP_KEY из `.dev.vars`. Сохранения в этом режиме настоящие.

## Первичная настройка Google, если потребуется заново

1. Откройте https://console.cloud.google.com/ → меню выбора проекта → «Создать проект». Дайте имя `finance-tracker`, дождитесь создания, выберите его.
2. «API и сервисы» → «Библиотека» → найдите **Google Sheets API** → «Включить».
3. «IAM и администрирование» → «Сервисные аккаунты» → «Создать сервисный аккаунт». Назовите его `finance-tracker`. Роль владельца проекта не нужна; доступ даётся через саму таблицу.
4. Откройте сервисный аккаунт → «Ключи» → «Добавить ключ» → «Создать новый ключ» → JSON. Сохраните файл вне репозитория. Скопируйте `client_email`.
5. Откройте свою Google-таблицу → «Поделиться» → вставьте e-mail сервисного аккаунта → роль «Редактор» → подтвердите. Не открывайте публичный доступ по ссылке.
6. ID таблицы находится в её адресе между `/d/` и `/edit`. Сохраните его только в `.dev.vars` / секреты Worker.
7. Проверьте вручную `Ввод данных!G1 = ID`, `H1 = Источник`. Сейчас эти столбцы уже добавлены. Если они отсутствуют в новой копии, введите только эти заголовки. Не меняйте F и не перемещайте строки.
8. Убедитесь, что A отформатирована как дата, C содержит выпадающий список из справочника, F2 — действующая ARRAYFORMULA. Даты приложение пишет числом Sheets; уже настроенный формат A определяет отображение.

Официальная инструкция ключей: https://cloud.google.com/iam/docs/creating-managing-service-account-keys . Названия пунктов могут отличаться в английской локализации.

## Настройка секретов

1. Не перезаписывайте существующий `.dev.vars`: он уже заполнен. На новой машине можно начать с `.dev.vars.example`, заменив `<<…>>`. JSON сервисного аккаунта должен быть одной строкой в одинарных кавычках, переносы private_key представлены `\n`.
2. APP_KEY — длинный случайный код, например сгенерированный менеджером паролей. Не ставьте его в URL, README или Git.
3. Выполните:

   ```powershell
   npx.cmd wrangler login
   npx.cmd wrangler whoami
   npm.cmd run smoke:read
   ```

4. Команда smoke читает реальные данные и сравнивает месячные суммы; записи отсутствуют в её коде. При ошибке проверьте доступ сервисного аккаунта, ID, названия листов и JSON.

## Публикация и обновление

1. Выполните полный набор проверок:

   ```powershell
   npm.cmd run check
   npm.cmd run build
   npx.cmd playwright install chromium
   npm.cmd run test:e2e
   node scripts/check-secrets.mjs
   ```

2. Загрузите секреты и опубликуйте:

   ```powershell
   npx.cmd wrangler secret bulk .dev.vars
   npm.cmd run deploy
   ```

   Допустим и ввод по одному, когда локального файла нет:

   ```powershell
   npx.cmd wrangler secret put GOOGLE_SERVICE_ACCOUNT_JSON
   npx.cmd wrangler secret put APP_KEY
   npx.cmd wrangler secret put SHEET_ID
   ```

   Команды `secret put` спрашивают значение скрыто. При первой загрузке `secret bulk` Wrangler может создать Worker. Используются имя `finance-tracker`, бесплатный `workers.dev` и Durable Object в том же Worker. DNS и пользовательские домены не требуются.
3. Откройте напечатанный `https://finance-tracker.…workers.dev`. Войдите с APP_KEY. Открытие приложения читает таблицу, но не записывает её.
4. Проверка опубликованного API без вывода ключа:

   ```powershell
   node scripts/verify-deployment.mjs https://<<WORKER_URL>>
   ```

   Скрипт берёт APP_KEY из `.dev.vars`, проверяет health, bootstrap, отсутствие mock и совпадение сумм; выполняет только GET.
5. После обновления полностью закройте и снова откройте установленное PWA. Оболочка версионируется хэшем сборки. Если видите старый интерфейс, обновите вкладку с интернетом. Не очищайте хранилище сайта при незавершённой очереди.

## Установка на Samsung Galaxy S25 FE

1. Откройте HTTPS-ссылку Worker в Chrome (не внутри мессенджера).
2. Введите код доступа, дождитесь загрузки категорий.
3. Chrome → ⋮ → «Добавить на главный экран» / «Установить приложение» → подтвердите. Запустите значок «Finance Tracker».
4. Отключите сеть и откройте приложение: после первого онлайн-запуска оболочка должна загрузиться. Запись при этом реальная, но стоит в очереди; добавляйте только настоящую трату.
5. Включите сеть, откройте приложение → «Ещё» → «Синхронизировать». Ожидайте «Все записи отправлены».

Физический телефон и установка через меню Android не автоматизировались. Chromium mobile e2e проверяет манифест, PNG-иконки, регистрацию SW и офлайн-перезагрузку.

## MacroDroid и настоящие уведомления

1. Выполните [MACRODROID.md](MACRODROID.md).
2. Получите по одному настоящему тексту Wallet/Kaspi для покупки, исходящего перевода, входящего и перевода себе. Не публикуйте номера карт/счетов.
3. Подгоните регулярки по этим текстам; добавьте обезличенные примеры в `tests/unit/logic.test.ts` и проверьте `npm.cmd test`.
4. Начните с открытия формы. Режим полностью автоматической записи включайте только после проверки классификации уведомлений и стабильного ID события.

## Что намеренно не проверялось записью

В задаче редизайна от 31 октября 2026 живые записи полностью запрещены и не выполнялись. Развёртывание проверяется только `verify-deployment.mjs` (GET). Обычные unit/API/e2e используют mock. Исторический `audit-live-smoke.mjs` относится к прежней отдельно разрешённой проверке, не запускается npm-командами и не является частью текущего процесса проверки.

## Ручная проверка редизайна

На физическом телефоне остаётся проверить TalkBack/VoiceOver, настоящую клавиатуру, вибрацию, безопасные жесты закрытия, вырезы и системное масштабирование. На ПК — реальную установку PWA в Chrome/Edge и меню масштаба браузера. Эти проверки не требуют тестовой записи в таблицу. Покупки и уведомления проверяйте только на собственных настоящих событиях; новый live smoke этим заданием не разрешён.

## Настройки Finance Tracker

Откройте «Ещё → Настройки» и нажмите «Создать», только когда будете готовы импортировать старые категории и статьи. Подтверждение создаёт лишь FT Categories и FT Items; старые листы не изменяются. При сбое повторите эту же кнопку. В месяцах без данных продолжается последняя сумма статьи. После импорта источником настроек становятся FT-листы. Проверка списка категории в самом Google Sheets по старому справочнику может требовать вашей ручной актуализации.

Создание FT-листов и переименование категорий на боевой таблице разработчиком не выполнялись. Проверьте их своим действием в интерфейсе. Если установленное PWA сохраняет прежнее имя, отправьте офлайн-очередь и переустановите PWA: новое имя Finance Tracker задаётся manifest.
