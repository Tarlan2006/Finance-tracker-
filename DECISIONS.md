## Итоговые решения аудита 30 октября 2026 (заменяют прежние ограничения ниже)

- Выход удаляет историю bootstrap и код из localStorage, закрывает другие вкладки через storage event, игнорирует запоздалые ответы. Непустая очередь шифруется AES-GCM ключом, производным от прежнего кода. Перенос в зашифрованное хранилище и удаление открытых записей — одна транзакция IndexedDB под Web Lock. Потеря прежнего кода или очистка данных сайта означает потерю неотправленных записей; интерфейс это объясняет. При активном входе код и очередь доступны origin: это доверенное личное устройство, не защита от вредоносного расширения или доступа к разблокированному профилю.
- HTML 200/404, неправильный JSON и ответ с чужим ID не подтверждают запись. Временные ошибки повторяются с прежним ID; постоянные JSON 4xx остаются для исправления, без бесконечной автоматической отправки. Навигация при HTTP 404/5xx может использовать кеш оболочки; API никогда не кешируется service worker.
- Удаление находится в правке, свайпы удаления исключены. Для очереди и журнала есть 5 секунд на отмену. Уход со страницы отменяет ещё не выполненное удаление из очереди. Если за это время очередь уже отправилась, приложение сообщает об этом и предлагает удалить запись через журнал.
- Текущий день обновляется при фокусе/возвращении и каждые 30 секунд; перед записью «Сегодня/Вчера» вычисляются заново. Вручную выбранная дата сохраняется и явно подписывается. Сдвиг даты конкретной прежней покупки не исправлялся без достоверной причины.
- Клавиатура определяется через visualViewport и фокус. Над ней фиксируются сохранение и текущая сумма с переходом к цифровому вводу; активное поле прокручивается выше панели. Проверка viewport синтетическая, физическая клавиатура Samsung не проверена. Источник API: https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport .
- Категории 80 px и 13 px для подписи — явное исключение из общей шкалы шрифтов по заданию. Дата визуально 42 px внутри цели 48 px. При большом шрифте строки могут расти для доступности; полные названия доступны через aria-label/title. Карточки чисел сокращают только то, что не помещается, и сохраняют полное значение в доступном имени.
- Заголовки API/статических assets проверяются отдельно. Отпечаток учитывает исходные значения текстовых ячеек до нормализации; клиент передаёт его для DELETE в JSON, чтобы не включать названия и комментарии в URL. Старый query-формат ещё читается для совместимости.
- Google Sheets не предоставляет compare-and-swap для values: приложение сериализует собственные запросы в одном Durable Object, но не может заблокировать ручную правку в Sheets между проверкой и записью. Не редактируйте ту же строку одновременно двумя способами.
- Новые major-версии инструментов сборки не внедряются в исправление интерфейса: npm audit не обнаружил уязвимостей, текущий lock проверен. Лицензии LGPL/MPL относятся к инструментам разработки/бинарным зависимостям, React/ReactDOM распространяются с MIT. Метаданные лицензий сохранены в отчёте; это инвентаризация, не юридическое заключение.
- Единственный live smoke выполняется через опубликованный API и его существующий Durable Object после зелёных проверок и deploy. Это перестановка шагов 5/6: так проверяется новая версия без второго независимого писателя в боевую таблицу. Скрипт создаёт локальный маркер до POST и запрещает повторный запуск; очистка ограничена точным ID/source/name.

## Аудит по обратной связи с телефона

- Исходное состояние 2c49ec5: 60 unit/API и 14 e2e зелёные. Новые регрессии до исправления: 10 отказов / 39 новых проверок. Скриншоты исходного интерфейса сохранены в tests/screenshots/audit/before.
- Введён отказ sheet_full (422) при попытке добавления после 1006; никаких расширений листа или формулы автоматически. Очередь позволяет исправить ситуацию и повторить.
- Отпечаток v2 включает дату, сумму, категорию, название, комментарий, ID и источник. Старый клиент при PATCH/DELETE получит 409 и должен обновиться; принимать слабый старый fp небезопасно. Повтор POST с существующим ID ищется до валидации справочника.
- Дата — календарная строка. Текущий день определяется Intl в TZ; UTC используется только как числовая координата календарной арифметики и serial Sheets, не для определения «сегодня». toISOString для дат расходов исключается. Время 30 октября 22:53 Asia/Almaty корректно соответствует 30 октября; причину конкретного выбора «29» без событий телефона установить нельзя.
- Подсказки показываются в нижнем регистре, ручной ввод сохраняет регистр. Перестановки слов объединяются; союзы/разделители и сочетания бытовых действий «магаз/покушать/кино/компы» отбрасываются. Это ограниченная эвристика, не семантическая классификация любых названий.
- Предупреждение о дубле ограничено временным окном и той же категорией; серверная идемпотентность по ID остаётся без временного окна.
- Защитные заголовки статики задаются _headers, поскольку asset-first обходит fetch Worker. Источник: https://developers.cloudflare.com/workers/static-assets/headers/ .

## Архитектура

- Durable Object внутри того же Worker последовательно выполняет операции по одной таблице: обычная переменная-мьютекс не защищает от разных изолятов Cloudflare. SQLite binding доступен на бесплатном плане. Это предотвращает гонки клиентов приложения; внешнее ручное редактирование Sheets не имеет атомарного compare-and-swap и требует осторожности.
- Добавление выбирает первую пустую A:D, как явно требует правило 2.4, включая очищенные строки. F и заголовки никогда не изменяются.
- Все /api/*, включая health, требуют X-App-Key (буквальное правило раздела 5).
- Даты: TZ=Asia/Almaty из ТЗ (тот же UTC+5, что пользовательский Asia/Qyzylorda). Дата Sheets — числовой serial, текстовые поля записываются RAW против формул-инъекций; формат колонки A сохраняется.
- Разработка по умолчанию принудительно mock, чтобы npm run dev и e2e не использовали имеющиеся секреты.
- Необязательное редактирование доходов/лимитов не включено: справочник и сводка остаются только для чтения.

## Проверки и уточнения по ходу работы

- Wrangler авторизован; реальные секреты валидны. Read-only smoke прочитал 156 расходов, 9 категорий и месяцы 2026-09…2026-12. Суммы всех четырёх месяцев совпали со сводкой, записей 0.
- Vitest и sharp обновлены после npm audit; итог установки — 0 известных уязвимостей. Для запуска esbuild/Chromium в этой Windows-среде нужны разрешения инструмента за пределами песочницы; пользовательские системные политики не менялись.
- В API quick при save=true обязателен id. Это дополнение к краткому телу в ТЗ необходимо для безопасных повторов автозаписи. save=true и числовое save=1 поддерживаются.
- Фоновой отправке нужен APP_KEY: кроме localStorage он хранится в IndexedDB meta, удаляется при выходе. Очереди разных кодов разделены SHA-256 отпечатком. Это не шифрование устройства; тот же origin имеет доступ к локальным данным.
- Сравнение названий дублей сохраняет цифры: «Заказ 123» и «Заказ 456» различны. Нормализация без цифр применяется только к подсказкам.
- Офлайн-оболочка восстанавливает кешированный HTML новым Response: Cloudflare перенаправляет index.html на /, а перенаправленный Response нельзя непосредственно использовать для offline navigation.
- PWA проверено в Chromium с параметрами телефона, физическая установка на Samsung и реальные уведомления не имитируются. Цель 500 мс для живого POST не измерялась: SMOKE_WRITE не включён.
- Необязательные лимиты/доходы, импорт Excel и сверка банковской выписки отложены. Режим quick реализован и протестирован на mock, MacroDroid-автоматизация остаётся ручной настройкой.
- Этапы фронтенда 5–8 реализованы совместно для общей проверки очереди и оболочки; проверки запускались на работающем интегрированном результате, коммиты разделены по функциям. Это отступление от отдельного тестового прогона сразу после каждой вкладки.
- Финальная проверка dev выявила разные Host/Origin у Vite и Worker. В локальном прокси включён changeOrigin и заменяется только ожидаемый localhost Origin. На опубликованном сервере CORS по-прежнему закрыт. Подтверждено: dev bootstrap 200, mock=true, пустой POST 422.
- Редактирование, удаление и ручной повтор очереди используют тот же Web Lock, что и фоновая отправка: запись, уже ушедшая в Sheets, не возвращается в очередь при правке.
- После первого deploy несколько запросов к workers.dev вернули платформенную HTML-страницу 404. Активная версия в Cloudflare была правильной; повторно применён маршрут командой wrangler triggers deploy. Последующий полный read-only smoke прошёл: health 200, bootstrap с реальными 156 строками, совпадение сумм, без ключа 401. DNS и пользовательские домены не менялись.
- После финального deploy платформенная 404 тоже встретилась. Скрипт проверки теперь делает не более четырёх повторов только HTML-404/5xx с backoff, не принимает их за успех. Финальный smoke прошёл с одним повтором. Точная причина нестабильности Cloudflare не установлена и описана в MORNING_REPORT.md; ошибка API в JSON повтором не маскируется.

# Редизайн: фаза 3

- Главный экран — журнал. Три раздела и отдельная кнопка добавления; глубокая ссылка сама открывает форму. Черновик сохраняется при закрытии формы в текущей сессии, после выхода очищается.
- Все суммы обзора считаются чистыми функциями из истории, с округлением в копейках. Неделя — календарные понедельник–воскресенье в Asia/Almaty. Незавершённый период сравнивается с тем же количеством дней предыдущего, короткий месяц ограничивается последним днём.
- В месячном графике 31 цель по 32 px не помещается на телефон. Выбрана внутренняя горизонтальная прокрутка графика с подсказкой; страница по горизонтали не прокручивается. Семь дней недели видны целиком.
- Малые категории объединяются только в кольце. Легенда и итог учитывают все записи, включая пустую и удалённую из справочника категорию. «Показать все» передаёт период и набор категорий в журнал.
- В недельном режиме доход/остаток показаны с явным названием месяца окончания недели: источник содержит месячные сводки, дробить доходы по неделям было бы недостоверно. Лимиты в недельной легенде обозначены как месячные.
- Палитра из девяти цветов задана централизованно; стабильный хеш названия не зависит от порядка справочника. При более чем девяти названиях цвета могут повторяться; текст и суммы сохраняют различимость.
- Старые e2e сохраняют бизнес-проверки. Изменены только вход в форму, переходы между тремя разделами, начальный экран второй вкладки, заголовок нового обзора и путь скриншотов. Устранена гонка тестового помощника: он ждёт готовности данных перед выбором уже открытой глубокой ссылки.
