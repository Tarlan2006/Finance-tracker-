# ЗАДАНИЕ ДЛЯ CODEX: плавные анимации и «ощущение» интерфейса в стиле Apple

Приложение работает и опубликовано (https://finance-tracker.tarlan-b06.workers.dev). Теперь нужно сделать так, чтобы всё **двигалось плавно, мягко и осмысленно**: переходы между экранами, листы и окна, графики, списки, переключатели, сохранение и удаление. Это работа **только над интерфейсом** (`web/`, при необходимости `shared/` для чисто визуальных вычислений). Логику данных, `worker/` и запись в Google Sheets **не менять**.

Я могу спать, вопросов нет: решай сам, записывай решения в `DECISIONS.md`, итог в `MOTION_REPORT.md`. Перечитай `CODEX_PROMPT.md`, `AGENTS.md`, `DESIGN_REPORT.md`. Все жёсткие правила остаются в силе: таблица боевая, **живую запись не выполнять**, браузерные тесты только на mock, `git push` не делать, секреты не коммитить, `npm.cmd` / `npx.cmd`.

## 1. Принципы (как у Apple)

- **Движение объясняет, а не украшает:** показывает откуда пришёл элемент, куда ушёл и что изменилось. Никаких анимаций ради анимаций, ничего мигающего, подпрыгивающего или «игрового».
- **Быстро и мягко:** обычные переходы 180–280 мс, крупные (листы, смена экрана) до 350 мс. Кривые с мягким завершением (подбери `cubic-bezier` или `linear()`-пружину с едва заметным перелётом для листов и кнопок; для уходящих элементов быстрее, чем для приходящих).
- **Отзывчивость превыше всего:** нажатие даёт мгновенный отклик (масштаб 0.97 и лёгкое затемнение за ≤ 80 мс). Анимация никогда не задерживает действие и не блокирует ввод: пользователь может нажать, пока что-то ещё едет.
- **Единый набор токенов движения** в `tokens.css`: длительности (`--dur-fast/base/slow`), кривые (`--ease-out`, `--ease-in-out`, `--spring`), расстояния (на 8–16 px, не на пол-экрана). Никаких «магических» значений в компонентах.
- **Производительность:** анимируй только `transform` и `opacity` (изредка `clip-path`/`stroke-dashoffset` для графиков). Не анимируй `width/height/top/left/margin`, тяжёлые `filter`/`box-shadow`. `will-change` ставь точечно и снимай после анимации. Цель: плавные 60 fps на среднем Android и 120 fps на Samsung S25 FE, без прыжков вёрстки (layout shift).
- **Доступность:** при `prefers-reduced-motion: reduce` все перемещения и масштабирования заменяются мгновенной сменой или коротким (≤ 120 мс) плавным появлением без движения. Никаких мерцаний чаще 3 раз в секунду. Состояния не должны быть понятны только по движению.
- **Без новых тяжёлых зависимостей.** CSS-переходы, Web Animations API и, где доступен, View Transitions API (с безопасным запасным вариантом без него). Если нужна небольшая библиотека, она должна весить меньше 8 КБ gzip, иначе пиши самостоятельно. Суммарный JS не больше ~100 КБ gzip.

## 2. Что анимировать (по экранам)

### Навигация и экраны
- Смена раздела «Траты / Обзор / Ещё»: мягкое перекрёстное появление с едва заметным сдвигом (8–12 px) в сторону вкладки; индикатор активного пункта плавно **скользит** между пунктами (одна «капсула», не по-отдельности).
- Плавающая навигация и кнопка «+»: при прокрутке вниз панель аккуратно уменьшается/приглушается, при прокрутке вверх возвращается; «+» при нажатии слегка проседает, при открытии экрана добавления плавно разворачивается из своей позиции.
- Экран «Добавить» на телефоне: поднимается снизу как лист (с лёгкой пружиной), закрывается свайпом вниз с «приклеиванием» к пальцу и инерцией; фон за ним затемняется и слегка уменьшается. На ПК диалог плавно появляется (масштаб 0.98 → 1 + fade) и закрывается обратно.
- Боковая панель на ПК и переключение в master-detail: панель деталей выезжает/проявляется без прыжка колонок.
- Открытие правки записи: лист/панель поднимается так же, как «Добавить».

### «Добавить» и сохранение
- Нажатия по цифрам и категориям: мягкая реакция (масштаб, фон), выбранная плитка категории плавно подсвечивается и получает галочку (без смены размера).
- Выпадающий список подсказок: появляется под полем с короткой анимацией высоты через `clip-path`/`opacity` (без скачка), строки по очереди (stagger ≤ 30 мс).
- **Успешное сохранение:** кнопка «Сохранить» превращается в галочку (≈ 400 мс), вибрация как сейчас, форма плавно очищается; запись «влетает» в журнал сверху своей группы дня с подсветкой, которая затухает за 1 секунду. Ошибка: короткое горизонтальное «встряхивание» поля (≤ 6 px) и красная подсветка, не больше 300 мс.
- Предупреждение о дубле и подтверждения: плавное появление/исчезновение.

### «Траты»
- Строки списка при первой загрузке мягко проявляются с каскадом (не больше первых 10 строк, остальные без анимации); при смене месяца список аккуратно перекрёстно меняется.
- Удаление: строка схлопывается по высоте и уходит; во время 5 секунд «Отменить» плашка снизу выезжает с таймером-индикатором; отмена возвращает строку на место с плавным раскрытием.
- Полоса прогресса лимита месяца плавно заполняется до значения (анимация `transform: scaleX`), цвет статуса меняется без дёрганья.
- Сверху «Сегодня/Вчера/…»: липкие заголовки дней при прокрутке плавно получают размытый фон.
- Состояния «синхронизируется / в таблице / ошибка» меняются плавной сменой значка, без прыжков.

### «Обзор»
- Переключатель «Неделя | Месяц»: скользящая капсула; при смене режима столбцы графика плавно **перестраиваются** (морфинг высоты и положения через `transform`, без пересоздания всего графика), подписи оси мягко проявляются.
- Смена периода стрелками ‹ ›: график слегка сдвигается в сторону движения и проявляется, итоговая сумма **плавно пересчитывается** (счётчик за ~400 мс с `tabular-nums`, без изменения ширины блока и без прыжка при быстрых нажатиях; при reduced motion мгновенно).
- Столбцы при первом показе вырастают снизу вверх с каскадом (≤ 20 мс на столбец, общее время ≤ 500 мс). Выбор столбца: мягкая подсветка, всплывающая подпись «Пн, 27 окт · N ₸» плавно появляется.
- Кольцо категорий: сегменты при первом показе «рисуются» по кругу (`stroke-dashoffset`, ≤ 600 мс); выбор сегмента/строки легенды: выбранный чуть выдвигается наружу, остальные плавно тускнеют до ~35%, центральный текст меняется кросс-фейдом с цифрами-счётчиком; повторное нажатие плавно возвращает всё обратно. Тот же эффект при выборе через клавиатуру.
- Список «Траты категории» под кольцом раскрывается плавно по высоте.
- Полосы бюджета категорий заполняются при показе и при смене периода.

### Общее
- Загрузка: вместо пустоты скелетоны с очень мягким мерцанием (отключается при reduced motion); переход от скелетона к данным кросс-фейдом.
- Тосты и плашки: плавно выезжают/исчезают; офлайн-плашка появляется без толчка вёрстки.
- Смена темы: плавная смена цветов фона и текста за 200 мс (только при смене системной темы, не при первой загрузке).
- Hover (ПК): тонкие переходы цвета/фона 120 мс, без движения; фокус: плавное появление кольца.
- Пустые состояния: мягкое появление иконки и текста.
- Pull-to-refresh на телефоне в «Тратах» (если получается надёжно и без конфликтов с прокруткой; иначе пропусти и запиши в отчёт).

## 3. Реализация и ограничения

1. Сделай небольшой общий слой движения (`web/src/motion/`): хук `usePrefersReducedMotion`, утилиты для переходов смены экрана, счётчика чисел, каскада, схлопывания по высоте. Компоненты используют их, а не собственные копии.
2. Для перехода между разделами используй **View Transitions API**, где он поддерживается (Chrome/Edge на Android и ПК), с запасным вариантом на CSS (fade), чтобы ничего не ломалось в браузерах без него.
3. Жесты (свайп листа вниз, свайп-назад) делай на Pointer Events, с `touch-action`, чтобы не конфликтовали с вертикальной прокруткой; не блокируй прокрутку страницы.
4. Не используй `setInterval` для анимаций; применяй `requestAnimationFrame` или CSS/WAAPI, останавливай анимации, когда вкладка скрыта.
5. Анимации не должны менять поведение: DOM после окончания анимации идентичен прежнему, `aria-*` и фокус корректны на каждом шаге (при открытии листа фокус внутрь, при закрытии возвращается на кнопку).
6. Не допускай накопления анимаций: быстрые повторные нажатия отменяют предыдущую анимацию и начинают новую с текущего состояния.

## 4. Тесты и проверка

1. **Все прежние тесты остаются зелёными** (121 unit/API и 58 e2e). Для детерминизма e2e включи в Playwright эмуляцию `reducedMotion: 'reduce'` по умолчанию и добавь отдельные тесты, которые **без** reduced motion проверяют, что анимированные элементы приходят в правильное конечное состояние (не застревают, не дублируются, нет утечек анимаций).
2. Новые unit-тесты для утилит движения (счётчик чисел: монотонность, конечное значение точное, отмена при новом значении; каскад; расчёт задержек).
3. Проверки для reduced motion: в этом режиме нет перемещений и масштабирований, смена мгновенная.
4. **Производительность:** замер на эмуляции CPU ×4 (CDP `Emulation.setCPUThrottlingRate`): нет длинных задач (> 50 мс) во время основных переходов, нет layout shift (CLS ≈ 0) при анимациях, нет мигания контента. Запиши цифры.
5. Визуальная проверка: запиши короткие видео/покадровые снимки ключевых переходов (смена вкладки, открытие листа добавления, сохранение, переключение «Неделя/Месяц», выбор сегмента кольца, удаление с отменой) в `tests/screenshots/motion/` (без личных данных, только mock), **посмотри их сам** и исправь рывки, прыжки, наложения и мерцание.
6. Размер: JS не больше ~100 КБ gzip, CSS не больше ~10 КБ gzip.
