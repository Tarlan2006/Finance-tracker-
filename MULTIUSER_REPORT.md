## Схема хранения и изоляция

- ACCOUNTS → AccountsDO / accounts-v1, миграция Wrangler v2-accounts, SQLite-backed storage. Через KV API SQLite атомарно сохраняется состояние accounts-v1: аккаунты, хеши сессий, ограничения частоты. Это не Workers KV и не секреты Worker.
- Аккаунт: постоянный ID, login, displayName, соль/итерации/хеш PBKDF2, mustChangePassword, disabled, sheetId, даты создания/смены, отдельный постоянный ключ очереди. Первичный ID Tarlan — tarlan, остальные UUID. Пароль в открытом виде не сохраняется.
- Сессия: случайные 32 байта; в SQLite только SHA-256 токена, отдельный публичный ID сессии, accountId, User-Agent до 200 символов, даты, скользящие 180 дней. Максимум 20 активных устройств на аккаунт. Выход отзывает текущую, смена пароля — остальные, административный сброс — все.
- AccountsDO определяет таблицу по сессии, заменяет внутренние заголовки маршрутизации и выбирает SheetCoordinator по accountId + sheetId. Параметры URL, тела и клиентские заголовки не меняют выбор таблицы. Google credential используется только на сервере. Сетевое ожидание одной таблицы не держит очередь авторизации/других таблиц.
- Ревизии, планы операций, настройки и Google-кеш принадлежат отдельному актору таблицы. На устройстве bootstrap, тема и режим обзора разделены по accountId. При выходе история очищается, очередь шифруется AES-GCM. Ключ очереди не зависит от пароля/токена, поэтому смена пароля её не теряет.
- Старая очередь восстанавливается только при входе tarlan: исходные ID сохраняются, бывший ключ используется локально для старого шифротекста. Вход Aru её не показывает и не отправляет. Сессия публикуется другим вкладкам после завершения миграции очереди. Глубокая ссылка сохраняется в sessionStorage на время входа, URL очищается сразу, временная копия удаляется после загрузки данных.

## PBKDF2 и CPU

Выбрано **100 000 итераций PBKDF2-SHA-256**, соль с 16 случайными байтами энтропии. Используется WebCrypto, без новых зависимостей и без паролей/хешей в выводе. Повторяемая команда: node scripts/benchmark-passwords.mjs.

Измерение на установленном локальном workerd: 20 последовательных derivations на вариант; CPU — разница TotalProcessorTime процесса Windows, wall — внешние часы. Импорт ключа один раз на группу; это оценка стоимости derivation, не полный HTTP-вход.

| Итерации | CPU на хеш, мс | Wall на хеш, мс |
|---:|---:|---:|
| 50 000 | 19,53 | 20,72 |
| 100 000 | 35,94 | 36,49 |
| 200 000 | 72,66 | 72,87 |
| 600 000 | 214,84 | 217,50 |

Локальный workerd допускает более 100k, но текущий production limit-enforcer платформы ограничивает PBKDF2 100k; изменение потолка до 1M ещё обсуждается: [Cloudflare workerd PR 7550](https://github.com/cloudflare/workerd/pull/7550). Поэтому выбран максимум, совместимый с этим потолком. Хеширование выполняется в DO, для которого документирован стандартный лимит **30 секунд CPU**: [лимиты Durable Objects](https://developers.cloudflare.com/durable-objects/platform/limits/). Замер CPU удалённого сервера и конкретного биллингового тарифа **не выполнялся**; локальные числа не выдаются за production CPU. Диагностический endpoint на боевой адрес не добавлялся.

Сетевой перебор: отдельные счётчики IP+login и login, 5 ошибок → 15 минут, затем удвоение до 24 часов. Успех сбрасывает счётчик. Доверенные сессии продолжают работать при блокировке пароля. Неизвестный логин проходит ту же PBKDF2-работу с фиктивным хешем; ответ совпадает с неверным паролем. Есть отдельные лимиты списка, login/IP и admin, Retry-After и ограничение объёма состояния. Пароли 5–128 символов; интерфейс советует длинную уникальную фразу, но не запрещает простой пароль владельца.

## Подготовка пустой таблицы

TablePreparation/GooglePreparation отделены от обычного GoogleSheetsAdapter. Старт запрещён при существующем журнале или FT-листах. До записи сохраняется план с принадлежащими операции sheetId. Один атомарный batchUpdate создаёт листы, заголовки, формат A/D и формулу F2, только в режиме подготовки. Оставшийся пустой исходный лист не удаляется и не переименовывается.

Журнал: 1006 строк, A дата, B название, C категория, D сумма, E комментарий, F месяц, G ID, H источник. Формула ARRAYFORMULA(IF(A2:A1006="","",TEXT(A2:A1006,"yyyy-mm"))) взята из mock и контракта; за образцом в боевую таблицу не обращались. FT Categories/FT Items используют существующие заголовки. Восемь нейтральных категорий, лимиты 0; доходных/ежемесячных статей нет. Новая таблица не читает Справочник, Доходы и расходы или Дашборд.

При потере ответа повтор сверяет сохранённые ID и заголовки, не перезаписывает созданные листы. Mock проверяет и частичное создание. В обычном режиме расходы по-прежнему пишутся в первую пустую A:D, только A:E/G:H; F не затрагивается, строк нет append/insert/delete. Правка и очистка сохраняют проверку отпечатка, ограничение 1006 и идемпотентные ID.

## Угрозы и ограничения

- Минимум 5 символов — осознанный выбор владельца. 100k PBKDF2 не делает короткий пароль устойчивым к офлайн-перебору при утечке базы; для этого нужен длинный уникальный пароль. Блокировки защищают сетевой вход, не украденные хеши.
- Список логинов публичен. Блокировку известного логина можно использовать для временного отказа нового входа; уже доверенная сессия работает. Сброс выполняет администратор.
- Токен и ключ очереди доступны авторизованному браузеру. XSS, вредоносное расширение или доступ к разблокированному профилю угрожают данным. CSP/no-store/запрет API-кеша сохранены. Очередь шифруется при выходе; это не защита от владельца разблокированного устройства во время входа.
- Для серверного отзыва при выходе нужна сеть. Офлайн данные и очередь доступны своему ранее вошедшему аккаунту; отзыв на сервере станет известен при следующем соединении. Очистка данных сайта уничтожает локальную очередь. Старый зашифрованный остаток, пароль от которого утрачен, невозможно расшифровать криптографически.
- Администратор доверенный: он может сбрасывать пароли/привязки. Перед перепривязкой уже используемого аккаунта надо отправить очереди и отозвать устройства; неподтверждённые расходы остаются привязанными к аккаунту.
- Google Sheets не обеспечивает CAS против одновременного ручного редактирования. Подготовку/ручные структурные правки не надо выполнять одновременно с внешним редактором.
- Samsung Galaxy S25 FE, iPhone, Safari/WebKit, реальные системные менеджеры паролей, TalkBack/VoiceOver и установка PWA на физических устройствах **не проверялись**. Проверены Chromium, касания/клавиатура и размеры viewport.
- Боевые изменения таблиц, создание Aru, установка ADMIN_TOKEN, парольный сброс и привязка таблицы намеренно оставлены человеку. Git push не выполнялся.

## Точные шаги владельцу после деплоя (PowerShell)


Выполняет владелец. Автоматическая публикация не создаёт Aru и не меняет пароли. При первом API-запросе создаётся только Tarlan из прежних секретов; Google-таблица при этом не меняется. Публичный список аккаунтов содержит логины и имена. Все остальные данные доступны только по сессии.

1. Откройте приложение, выберите **Tarlan · tarlan** и введите прежнее значение APP_KEY в поле пароля. Убедитесь, что данные на месте и старая очередь отправилась. APP_KEY больше не работает как API-токен; он нужен только для начальной миграции. Не очищайте данные сайта до проверки очереди.
2. Из корня проекта создайте административный токен в переменной, не выводя его на экран, и загрузите секрет:

```powershell
$env:WORKER_URL = 'https://finance-tracker.tarlan-b06.workers.dev'
$env:ADMIN_TOKEN = node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))"
$env:ADMIN_TOKEN | npx.cmd wrangler secret put ADMIN_TOKEN
node scripts/accounts.mjs list
node scripts/accounts.mjs add aru Aru --must-change
```

Последняя команда дважды запросит пароль скрытым вводом. Не передавайте пароль аргументом, в URL или через командную историю. Сохраните ADMIN_TOKEN в менеджере паролей; при необходимости добавьте его в игнорируемый .dev.vars. Не создавайте новый токен при каждом запуске: после закрытия терминала загрузите сохранённое значение в окружение или .dev.vars. В .dev.vars.example только имена переменных, без значений.

3. Aru создаёт **пустую Google-таблицу** и даёт сервисному аккаунту доступ «Редактор». Привяжите её (замените текст в угловых скобках):

```powershell
node scripts/accounts.mjs set-sheet aru '<ссылка Google Sheets или ID>'
```

Команда выводит email сервисного аккаунта из конфигурации Worker; если доступ ещё не выдан, выдайте его сейчас до подготовки. Приватный ключ не выводится. Одну таблицу нельзя привязать к двум аккаунтам. При смене уже подключённой таблицы сначала отправьте очередь всех устройств и завершите их сессии; иначе неотправленные расходы аккаунта попадут в новую привязку.

4. Aru выбирает свой аккаунт, вводит временный пароль, задаёт новый, затем нажимает **«Подготовить таблицу»**. Старые таблицы с листом расходов эта операция не меняет. Добавляются журнал на 1006 строк, формула месяца, FT Categories и FT Items. Начальные лимиты — 0, доходных и ежемесячных статей нет: заполните их в настройках. Затем можно записывать траты.

Администрирование (все команды ниже изменяют аккаунты, выполняйте осознанно):

```powershell
node scripts/accounts.mjs list
node scripts/accounts.mjs set-password aru --must-change
node scripts/accounts.mjs revoke aru
node scripts/accounts.mjs disable aru
node scripts/accounts.mjs enable aru
# Отзыв отдельной сессии (ID из интерфейса/управления сессиями):
node scripts/accounts.mjs revoke aru --session '<ID сессии>'
```

Сброс пароля отзывает все сессии; смена пароля в приложении — остальные. «Ещё → Аккаунт» показывает устройства и позволяет завершить отдельный сеанс. Для выхода с серверным отзывом нужен интернет. Очередь при выходе шифруется постоянным ключом аккаунта и восстанавливается после входа в тот же аккаунт, даже после смены пароля. Браузерная очистка данных уничтожает неотправленную очередь.

Проверка публикации: node scripts/verify-deployment.mjs https://finance-tracker.tarlan-b06.workers.dev. Без VERIFY_LOGIN/VERIFY_PASSWORD проверяются только публичные endpoints и 401. Для чтения данных владелец задаёт эти переменные в игнорируемом .dev.vars; скрипт входит, читает и завершает свою сессию, не пишет в Sheets. Административный токен для этой проверки не нужен.
