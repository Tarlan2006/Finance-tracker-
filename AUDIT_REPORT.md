## Проверки целостности и безопасности

- [API-тесты](tests/api/api.test.ts) доказывают первую пустую A:D, сохранность F/заголовков/числа строк, восемь параллельных разных записей без перезаписи, параллельный повтор ID, повторное использование очищенной строки, 401/403/409/422/429. «Дырка» используется повторно согласно правилу A:D; физический порядок листа не пересортировывается, журнал сортируется по дате. Пустая A:D с оставшимся G/H блокируется как частичная ручная правка.
- [Google adapter tests](tests/api/google.test.ts): только RAW `A:E` и `G:H`, clear этих диапазонов, без F, append, deleteDimension и других листов; проверка подписи JWT, кеша токена, пакетного чтения и backoff 429/5xx. В коде записи нет команд структурной перестройки Sheets.
- Даты текущего дня берутся через Intl в `Asia/Almaty`; UTC применяется только как координата календарной арифметики и Google serial. Проверены 23:30/00:30 Алматы, 19:00 UTC, конец месяца/года, високосный февраль. Ручная дата переживает полночь; «Сегодня/Вчера» пересчитываются.
- Суммы вычисляются в копейках/тиынах, от 0,01 до 100 000 000. Запятая, десятичная точка, пробел/NBSP и выражение со сложением допустимы. 0, отрицательные, exponent, NaN, невидимый zero-width, арабские и полноширинные цифры отвергаются как неоднозначные. Тексты `=SUM`, `+1`, `-1`, `@x`, апостроф, HTML и похожие Unicode-символы остаются обычными RAW-строками; React выводит текст без innerHTML; CSV экранирует формульные префиксы. Ввод нормализует пробелы и ограничивает длину, но не меняет регистр вручную.
- Все `/api/*` проходят Auth до маршрута. Сравниваются SHA-256 фиксированной длины без раннего выхода по несовпадению. Лимит привязан к `CF-Connecting-IP`, другой IP не блокируется. Счётчик живёт в экземпляре DO, может сброситься при его пересоздании; NAT делит лимит между клиентами одного IP. Это защита от обычного перебора, не полноценный распределённый WAF.
- API: no-store, nosniff, no-referrer, CSP с frame-ancestors none. Статика имеет отдельные заголовки `_headers`. Ошибки клиента не включают stack, ID таблицы или email аккаунта. APP_KEY не включается в URL. Сервисный ключ остаётся на сервере.
- Service worker кеширует оболочку/статику, исключает `/api/*`. Вход использует localStorage+IndexedDB для работы офлайн, поэтому разблокированный профиль остаётся доверенной средой. После выхода финансовый кеш удалён, открытая очередь заменена шифротекстом. Очистка данных сайта необратимо уничтожает неотправленную очередь; старый код нужен для её расшифровки. Перед ротацией кода очередь следует отправить.
- Внешняя ручная правка между проверкой fp и сетевой записью в Sheets не блокируется: Sheets values API не даёт атомарный CAS. Собственные запросы приложения сериализуются одним глобальным DO. Это известное ограничение архитектуры, не обещание транзакционной блокировки Google UI.

## Очередь и пользовательские сценарии

Проверены offline → reload → online; закрытие вкладки с 200 записями; повтор с потерянным ответом **после** фактического commit; два окна; HTML 200/404; постоянный 422 с исправлением; повторное нажатие «Сохранить»; выход с непустой очередью и восстановление; отмена удаления. Все браузерные записи выполнялись только в локальном mock.

Синхронизация сохраняет исходный ID до подтверждения. Ошибки валидации не повторяются бесконечно автоматически; сетевые/5xx/429 используют backoff. Удаление из очереди в течение пяти секунд можно отменить; если запись за это время уже отправилась, интерфейс сообщает об этом, а не выдаёт удаление за успех.

Глубокая ссылка декодируется URLSearchParams, первое значение повторного параметра считается входным, amount/merchant удаляются из адреса до записи. Reload ссылки сам ничего не сохраняет. Подсказка категории использует историю и порог уверенности; неизвестное остаётся без автоматического выбора. Фильтры/поиск/итог дня/месяц и сравнение обзора с mock проверены. Нулевые лимиты не делят на ноль; отсутствующая сводка дохода отображается как «Нет данных».
