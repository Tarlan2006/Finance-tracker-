## Что удалось воспроизвести

На локальной копии прежней версии вошли как tarlan, сохранили через форму «тест · 100 ₸» и вернули HTTP 503 только на отправку расхода. Журнал продолжал открываться. Браузер был онлайн, карточка обещала отправку при появлении сети. Нажатие «Синхронизировать» в интервале ожидания оставило одну запись и не создало второго запроса. В тесте часы были зафиксированы, чтобы нажатие гарантированно пришлось на этот интервал.

В прежнем отправщике временная ошибка сохраняла только счётчик попыток и срок следующего повтора. Ручная синхронизация вызывала тот же отправщик, который прекращал обход при будущем `nextAt`. Интерфейс показывал одинаковую подпись для всех ожидающих записей. Это объясняет молчание приложения и бездействие кнопки. Первоначальную причину сбоя именно на Samsung установить по старой карточке невозможно. [Прежний отправщик, строки 95–122](https://github.com/Tarlan2006/Finance-tracker-/blob/0f9fc5c/web/src/lib/queue.ts#L95-L122) · [Вызов из интерфейса, строки 41–45](https://github.com/Tarlan2006/Finance-tracker-/blob/0f9fc5c/web/src/lib/useFinance.ts#L41-L45)

## Что изменилось

- Ручная синхронизация, открытие приложения и возврат сети запускают отправку без ожидания старого таймера. Фоновые повторы сохраняют задержку. Запись отправляется с прежними ID и версией привязки таблицы. Отправщик снимает её с очереди только после ответа с совпадающим ID. [Отправщик](web/src/lib/queue.ts#L114-L163) · [Возобновление](web/src/lib/useFinance.ts#L103-L110)
- Ожидание занятой Web Lock ограничено четырьмя секундами, сетевого ответа — двадцатью. При занятой очереди приложение показывает причину и допускает новый запуск после освобождения. Удерживаемая другой вкладкой блокировка сохраняет силу. [Блокировки](web/src/lib/queue.ts#L83-L100)
- При HTTP 401 отправка возвращает пользователя на экран входа. Незавершённая очередь сохраняется в зашифрованном виде для своего аккаунта. После входа восстанавливаются прежние записи. Серверные ограничения по аккаунту, таблице и ID действуют при каждом повторе. [Обработка сессии](web/src/lib/useFinance.ts#L37-L77)
- Карточка показывает причину сбоя. Постоянные ошибки данных остаются с действиями «Повторить», «Исправить», «Убрать». В «Ещё → Синхронизация» видны число ожидающих записей, время последней попытки, результат и HTTP-код, если он получен. Диагностика хранит категорию, время и статус отдельно для аккаунта. [Карточка](web/src/screens/Expenses.tsx#L48) · [Синхронизация](web/src/screens/More.tsx#L17) · [Категории результатов](web/src/lib/sync-result.ts)
- Worker различает отказ Google Sheets в доступе и ограничение частоты запросов. Это позволяет отличить проблему доступа к таблице от истёкшей пользовательской сессии. [Адаптер Google](worker/src/google-sheets.ts#L21-L25)
