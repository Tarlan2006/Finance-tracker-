## Хранение и безопасность

До подтверждения «Создать» работают прежний справочник и сводка. Приложение не создаёт служебные листы при входе или GET. Создание добавляет только FT Categories и FT Items; повтор не дублирует импорт, частичное создание листов восстанавливается. Заголовки и импорт записываются одним RAW batch.

Старые Справочник, Доходы и расходы, Дашборд остаются только для чтения. Обычные расходы пишутся в первую пустую A:D, диапазоны A:E/G:H. F журнала, формула F2 и физический порядок строк сохраняются. При переименовании/переносе разрешены лишь точные ячейки C; настройки записываются по ID/первой пустой строке в A:H служебных листов. Запрещённых append/insertDimension/deleteDimension и других структурных операций адаптер не использует.

Настройки проходят ту же последовательную очередь Durable Object. Каждая правка проверяет rev и повторно читает строки; конфликт возвращает 409. План операции сохранён до записи, с устойчивым operationId и частями по 50 записей. Проверены повтор после частичного обновления C, потерянный ответ и перезапуск API, включая журнал из 1005 записей. RAW batch объединяет C и служебные строки; внешний редактор Sheets всё ещё может изменить ячейку между последним чтением и записью — API Google не даёт условной записи по значению. Одновременных ручных правок следует избегать.

Импорт переносит последнее известное значение в месяцы без данных. Проверены зарплата 200 000 с сентября; стипендия 52 000 в сентябре / 60 000 с октября; Spotify 730; телефон 24 000; ИИ 5 432 / 9 000; депозит 60 000. Доходы и ежемесячные статьи после создания берутся из FT Items. Валидация категории в самом Google Sheets по старому Справочнику может устаревать; это указано в настройках.

Для сохранения схемы без удаления строк отменённые будущие сегменты имеют to_month раньше from_month и никогда не действуют. Подробные решения — DECISIONS.md.
